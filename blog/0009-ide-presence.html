AI 不会替我们分发：让插件跟人见面

RepoNest 的插件资产服务的一直是 agent，没有一样出现在开发者天天打开的界面上。ADR-0009 把「可见性」升级为产品级约束——先一键注册，再一个 VS Code 扩展，JetBrains 缓议。

RepoNest ·2026 年 10 月 2 日 ·约 6 分钟阅读

「装完就隐形」的资产

盘点 RepoNest 现有的分发资产——MCP server、dsh Harness 插件、llms.txt——它们服务的对象全部是 agent。MCP 工具只出现在 agent 的聊天面板里；命令面板、状态栏、侧边栏这些 IDE 原生界面上，RepoNest 不存在。装完之后，它就隐形了。

这个盲区构成两条传播上的硬限制。第一，agent 不会主动发现我们的插件：没有任何机制让一个新用户的 AI agent 主动说「你应该装 reponest-mcp」——分发必须由人来完成，而人只在自己天天打开的界面里发现工具。第二，口口相传需要可见的货架：当有人问「你用什么管理项目记忆」，如果答案是一个装完就隐形的 server，传播链在第一步就断了。

agent 不会替我们装插件——可见性必须由产品自己购买。
·  ·  ·

能力不缺，缺的是见面

需要先澄清的是：这不是能力空洞。VS Code（Copilot Chat）与 JetBrains（AI Assistant / 内置 MCP 客户端）都已原生支持 MCP 注册，接入文档也早已写明手动路径。真正的缺口只有两个：一是接入摩擦——新用户要手动改 .mcp.json；二是 IDE 内「人」的体验为零——没有命令面板里的一条 RepoNest: Handoff，没有状态栏上的「上次交接」，没有侧边栏的笔记检索。

换言之，工具能力在两大 IDE 家族里今天就能到位；要补的是见面，不是功能。

·  ·  ·

决策：先一键注册，再一个扩展

ADR-0009 的路径分三步。第一步是已经落地的一键注册：reponest-init 探测 reponest-mcp 二进制，向 Claude Code、Cursor、VS Code、Windsurf 写入注册，并可选安装会话结束的自动交接 hook：

node scripts/reponest-init/index.mjs --with-hook

第二步是一个 VS Code 扩展——而且是唯一的 IDE 扩展：命令面板三条命令（context / handoff / search）、状态栏显示上次交接时间、侧边栏笔记检索并跳转文件、首次使用引导一键注册。第三步是所有新资产共同遵守的薄客户端纪律：MCP 保持唯一执行接口，internal/service 保持单一事实源，扩展只是薄壳，零逻辑复制——与 dsh 插件同一范式。

·  ·  ·

为什么不是 IDEA 插件

VS Code 先行不是偏好，是算术：一份 VSIX 同时覆盖 VS Code、Cursor、Windsurf 整个 fork 家族——这是「一次投入、全家族见面」的唯一形态；而 JetBrains 插件一份构建只覆盖一家，还需要独立的 Kotlin / Gradle 代码栈，维护面直接翻倍。在收到真实需求信号（issue / star）并补写 ADR 论证之前，它不立项、不写代码。

这个取舍也顺手调和了范围冻结（ADR-0006）：冻结的从来是平台化基础设施——插件 SPI、HTTP server、多后端存储——而不是「跟人见面的分发面」。薄客户端纪律让新资产只随对外 API 演进，维护成本保持有界。

·  ·  ·

一条新的立项门槛

ADR-0009 还留了一条长期原则：分发评估门。今后每个分发资产立项时，必须回答「人在哪个界面上看见它」；只有 agent 能消费、人不可见的资产，需要说明它服务的是存量用户的深度，还是获客。可见性从此不是营销问题，而是产品自己要支付的成本。

第一步已经落地。
reponest-init 位于 scripts/reponest-init/，幂等、可 dry-run；M5 的 VS Code 扩展骨架也已落在 ide/vscode/。决策全文见 docs/adr/0009-ide-presence.md。
