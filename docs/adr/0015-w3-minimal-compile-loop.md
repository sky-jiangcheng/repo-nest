# ADR-0015: W3 最小编译闭环——LLM 只写 pending 页，人批准才进检索

- 状态：Proposed（schema v18 与编译器已实现并通过契约测试；晋升 Accepted 仍差"真实库上编译一轮并由人审"这一条，见末尾）
- 日期：2026-10-08
- 关联：[ADR-0014](0014-llm-wiki-knowledge-compiler.md)（本方案实现其决策 4 与决策 5 的前半）、[ADR-0012](0012-semantic-search.md)、[ADR-0011](0011-multi-agent-memory-importers.md)、[ADR-0007](0007-session-memory-protocol.md)、TODO **M6-W3**；前置 W1（schema v16）、W1b（v17 页索引）、W4（lint）均已落地

## 背景

W1 给了结构，W2 给了消费端取证，W4 给了防腐检查。缺的是 ADR-0014 决策 4 的**摄入时编译**：让模型读一份来源，把它整合进页面层。

先说清为什么这一步必须重新决策而不是直接照 ADR-0014 开工——实现到 W1/W2 之后才发现一件事：**「先审后入 index」这句话在当前数据模型里无法表达**。

1. `wiki_pages` 只有 `id/slug/title/kind/project_id/content/created_at/updated_at`，没有状态列，也没有写入者列。
2. `SearchWikiPages` 与 `ListWikiPages` 都不带状态过滤，所以一页只要存在就立刻进检索、进 `index.md`、进 AskAI 证据块。

如果先上编译再补审，中间窗口里"未经审核的模型输出"会直接成为问答的证据来源——那是把 ADR-0014 明确拒绝的东西（幻觉被编译成看似已确立的知识）请进主路径。所以**状态列与检索过滤是和编译器同一个原子变更，不能拆成两步**。

## 决策（MVP 范围，共 7 条）

### 1. schema v18 先加两列，并把它们变成检索的谓词，再加编译器

```
wiki_pages.status  TEXT NOT NULL DEFAULT 'approved'
                   CHECK (status IN ('pending','approved','rejected'))
wiki_pages.source  TEXT NOT NULL DEFAULT 'manual'
                   -- manual | ai | wiki-compile | import:<source>
```

- 默认值必须是 `approved`：现存页面全部由人发起（应用内手写、W2 的"存为页面"按钮），它们本来就已被信任；把默认设成 `pending` 会让一次升级把用户的既有知识从检索里全部撤走。
- 迁移完成后，`SearchWikiPages` / `SearchWikiPagesMatch`（两处 FTS 查询）加 `p.status = 'approved'` 过滤，并加 `ListPendingWikiPages` 供审核面使用。**顺序很重要**：先有过滤，编译器才有地方写。
>
> **实现时对本条做了一处收窄**：原计划让 `ListWikiPages` 也过滤 approved，实测会把 **W1b 的导出旁路和 W4 的 lint 一起废掉**——pending 页正是导出要标出来给人审、lint 要检查的对象（`no-source` 那一条就是为编译器产物准备的）。因此落地为：**检索/取证路径过滤 approved，清点路径（导出、lint、审核队列）保留全部状态并显式带出 `status`/`source`**。这是"什么存在"与"什么可以回答问题"两个不同的问题，本条以现状为准。
- 可逆性沿用 W1 的标准：新增列而非新表，`DROP COLUMN` 即回到 v17 形状；迁移测试断言升级前已存在的页面在升级后仍可被检索到（否则"默认 approved"是一条会悄悄失效的注释）。

### 2. 编译单元 = 一条笔记，一次模型调用，严格 JSON 契约

不是"一个导入源"也不是"一个项目"。一条笔记是天然有界、可溯源、可幂等的单位：重跑同一笔记更新自己上次产出的 pending 页，不产生副本；一条失败不影响其它条。

模型只被允许输出一个 JSON 数组，元素是 `{op:"create_page"|"add_link"|"attach_note", ...}`；解析不出 JSON 就**一条都不写**（沿用 W4 的同一原则：幻觉出来的链接是要人手动清的噪音，而不是"部分成功"）。所有产出落在 `pending` + `source='wiki-compile'`。

### 3. 编译器**只能新建 pending 页，永远不能改已批准的页**

这是 MVP 的核心取舍，也是最需要被批准的一条。若某概念已有批准页而新来源要修订它，编译器**不修改该页**，而是产出一条 lint 风格的建议（落 `project_todos`），由人决定怎么改。理由：

- "让模型修订既有结论"正是 ADR-0014 里"更深一层的腐蚀"的具体发生位置——修改会覆盖掉人的判断，且 `note_versions` 那种快照机制在页面层还不存在；
- 只新建的写面是**可完全撤销的**：拒绝一个 pending 页 = 删一行，级联带走它的链接与笔记挂接，不留痕迹也不改动别人的东西；
- 它把"批准"变成一个只有人能触发的状态迁移，而不是模型可以自我完成的动作。

代价如实说：概念会分裂（同一主题出现两页待批），需要人在审核时合并。MVP 接受这个代价，因为它换来的是"编译器不可能悄悄改掉你已经认可的内容"。

### 4. 每页必须挂 ≥1 来源笔记，由 W4 兜底

编译器产出的每一页都要把它读的那条笔记写进 `note_pages`。W4 已有的 `no-source` 检查会在违规时产出告警——**防腐层反过来给生成层当守卫**，这是 W1/W4 先落地才有的性质。

### 5. 硬预算与"超即止"

默认上限（全部可配）：单次运行 ≤20 条笔记、每条 ≤6 页、每页正文 ≤1500 字节、单次总产出 ≤60 页。触及上限时**停止本轮并在报告里说明停在哪**，而不是把剩下的硬塞进去——预算存在的理由恰恰是"模型不知道什么时候该停"。

### 6. 开关与不可自动触发

- 新配置键 `wiki_compile`，默认关；另需已配置 AI 端点（复用 `ai_chat_*`，不新增 provider 面）。
- **不接任何定时器**：W2/W4 的 ticker 只覆盖读取侧与检查侧。编译必须由人显式按条/按项目点动，这是 ADR-0014"一次一源、人在环"的硬落地。
- **不进 `auto_import` 路径**：导入器只写笔记；笔记→页面永远是另一步独立授权的动作。
- **不新增 MCP 工具**：MCP 是给 agent 用的，而"agent 可以自己往库里写待审知识"正好绕开了本文要的人在环。桌面绑定 + `/api/rpc` 足够。

### 7. 隐私与外发面明确变宽

`semantic_search` 把笔记文本发出去换一次向量；本方案把笔记文本发出去**换回写进库的内容**。二者 consent 等级不同，所以是**独立的键**、默认各自关、互不连带。文档需写清：开启后，被编译的笔记（可能含仓库代码片段、会话摘录）会经你的 chat 端点，且模型回写的文本会持久化在本机库里。

## MVP 明确不做

synthesis 页自动重写、概念去重自动合并、矛盾驱动的修订、页面级向量索引、审核 UI、定时编译、跨项目编译、文件树双向同步（ADR-0014 决策 2）。审核界面在 MVP 用绑定 + 一个 CLI 视图（`reponest-wiki-export` 里带上 pending 标记）顶住，UI 审批页作为下一步单独评审。

## 后果

**正面**：第一次真正兑现"摄入时编译"，且写面小到可以完全撤销；W4 从"检查人的笔记"升级成"检查模型的产出"，形成闭环；pending/approved 分离让 AskAI 的证据块天然只含人已认可的内容。

**负面（不粉饰）**：token 成本随笔记数线性增长且不会自己停（靠预算硬拦）；模型产出仍可能是错的，只是**错误现在被隔离在 pending 里**，其代价转为审核负担——审核疲劳是这条路线最现实的失败模式，MVP 用预算上限与"每条一次编译"压住它，但没有根治；概念分裂会让图变脏；提示注入面变宽（一条写着"忽略以上指令"的笔记会进入 prompt，缓解手段是输出只接受 JSON、只能新建 pending、永不触达已批准页，而不是指望模型自律）。

## 晋升条件（Proposed → Accepted）

1. v18 迁移带可逆测试，且断言"升级前已存在的页面在升级后仍可被检索"；
2. 检索三处（`SearchWikiPages` / `SearchWikiPagesMatch` / `ListWikiPages`）与 AskAI 证据路径出现 pending 泄漏时有测试挡得住；
3. 契约测试：模型返回非 JSON → 零写入；返回不存在的 `page_id`/slug → 该条丢弃；编译产物 100% 带 `note_pages` 溯源；
4. 幂等：同一笔记编译两次不产生重复 pending 页；
5. 一次真实编译演练在你自己的库上跑通，产出被人审过一轮（这一步不能只靠 fixture——W2 的门禁教训是机制正确 ≠ 真实收益）。
