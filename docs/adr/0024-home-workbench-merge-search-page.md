# ADR-0024: 首页工作台化——首页与仪表盘合并、全局搜索独立成页、热门推荐

- 状态：Accepted（2026-10-16，用户直接提出）
- 日期：2026-10-16
- 关联：[ADR-0017](0017-one-kernel-two-entry-points.md)（本文修订其「界面对齐」一节的两栏并排措辞；「仪表盘不移出首屏、不默认隐藏」原则不变）、[ADR-0006](0006-scope-freeze.md)（仪表盘仍是支持能力，本文不新增后端能力）

## 背景

D25 / ADR-0017 落地后，`/`（Home）是「左栏记忆环 + 右栏内嵌完整 `<Dashboard />`」的两栏并排，而 `/dashboard` 路由又独立渲染同一个 Dashboard 组件。这带来三类问题：

1. **重复展示**：同一份「目标环 + 热力图 + 摘要 + 项目网格」在两个顶级路由各渲染一次，两个导航入口指向同质内容，后续每次仪表盘改动都要同时考虑两个容器。
2. **布局债务**：两栏并排在 ≤1080px 断点堆叠后首屏信息密度失衡——ADR-0017 晋升时就为此修过一个「记忆环塌陷、搜索框与 handoff 列表被仪表盘遮盖」的真缺陷；窄屏下两栏本质上是硬凑的。
3. **搜索没有落点**：全局检索散在三处（Home 内联输入框、⌘K CommandPalette、仪表盘项目搜索下拉），没有可直达的顶级入口；检索的「空态」——热门项目、热门标签——在弹层里没有承载空间，冷启动用户打开搜索只会看到一块空白输入框。

## 决策

1. **首页 = 工作台（单栏融合）**：`/` 重新设计为一条自上而下的叙事流：今日目标 hero（目标环 + 摘要）→ 热力图 → 记忆环条（最近 handoff 横排 + 醒目「全局搜索」入口）→ 控制行（日期 / 筛选 / 排序 / 重扫描）→ 项目网格 → 状态栏。删除 Home 左栏的内联搜索块与 handoff 纵列。`/dashboard` 路由改为重定向到 `/`，主导航去掉「仪表盘」项、新增「搜索」项。Dashboard 组件保留为首页引用的面板，功能不减、不默认隐藏。
2. **全局搜索独立成顶级页 `/search`**：大搜索框 autofocus，debounce 检索笔记与待办，结果按「项目 / 笔记 / 待办」分组，URL 同步 `?q=` 支持深链。⌘K CommandPalette 保留为键盘快速切换器，其首位动作（新建 handoff）不变。
3. **热门推荐落在 `/search` 空闲态**：无 query 时展示推荐区——热门项目 top 6（按最近个人新增行数降序，平局与全零时按星标、仓库数兜底）与热门标签 chips（点击即把标签词填入搜索框执行检索）。排序纯前端完成，不加后端字段、不动 schema。

## 理由

- 重复渲染是真实的维护成本与定位噪声；单栏融合让「记忆环 + 项目状态」从「两栏挤压」变成一条流，ADR-0017 的本意（两者同屏可见、叙事对齐）不受损，反而消除了窄屏布局这个长期例外。
- 搜索值得一个能承载「空态价值」的页面：没有 query 时用热门项目/标签给出落脚点，这是瞬态弹层做不到的；顶级页也让手册、快捷键与外部链接有稳定锚点。
- 不动后端是刻意的：现有接口已给齐排序所需字段（`my_added` / `is_starred` / `repo_count` / `ListAllTags`），本次是纯信息架构调整，把 schema 与统计口径的升级空间留给有真实需求信号的时候。

## 后果

- 正面：双路由重复渲染消除；窄屏布局复杂度下降；搜索有顶级入口与推荐位；Home.test / Search.test 直接钉住新结构。
- 负面：旧 `/dashboard` 链接（书签、文档引用）会被重定向，属一次性迁移；ADR-0017 的两栏措辞被本文修订，阅读旧文需回到注记；热门排序是客户端启发式（无历史活跃度加权），标签无热度计数，「热门」口径以页面标注为准。
- 边界：仪表盘资产（目标环、热力图、工作日告警）继续保留在首屏，ADR-0017「不移出首屏、不默认隐藏、不删除」的立场不变——变的只是容器：从独立路由并入首页，两栏并排改为单栏融合。
