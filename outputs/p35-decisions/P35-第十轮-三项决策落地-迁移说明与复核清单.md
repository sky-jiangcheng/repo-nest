## 一、执行结果

**1. `main.tsx` 导入顺序（已改，但要说清效果边界）**

`import './styles/index.css'` 已提到 `import App from './App'` 之前。实测结果分两面：

- **dev 模式**：样式注入顺序确实变了——设计系统 CSS 现在先注入，lazy 路由分片的 CSS 后注入，顺序与预期一致。
- **构建产物**：`index.html` 里的样式表顺序**没有变化**，仍是 `dashboard → knowledge → projectDetail → index`。原因是 Vite 会把异步分片的 CSS 排在入口 CSS 之前，这个顺序由 chunk 图决定，跟 `main.tsx` 里的 import 顺序无关。

所以这一行改动是「让 dev 与生产语义一致」，但**没有**解决第四轮那个「设计系统排在最后」的问题；doubled 选择器仍然必须保留。要真正改产物顺序，只有两条路，都需要你点头（都属构建配置/入口改动，影响每次构建）：
① `vite.config` 里设 `build.cssCodeSplit: false`——全部 CSS 合成一个文件，文件内顺序按模块图走，设计系统就会在前；代价是失去按路由拆分 CSS（对本地桌面应用影响不大）；
② 把设计系统 CSS 从 `main.tsx` 挪到 `index.html` 的 `<link>`，让它先于脚本出现——需要实测 Vite 是否保留这个位置。
