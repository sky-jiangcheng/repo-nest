## 二、边界判定依据

1. **跨组件共享类一律留全局**：`.badge` 基类（NoteSection 也用）、`.card-star`（ProjectSearchDropdown 也用）、`.skeleton`、`.toggle-row`（main.css 有 `.settings-group > .toggle-row` 跨文件后代规则）、`.sort-select` 与 `.cmdk-input`（嵌在 inputs.css 的共享族选择器组里）本轮都**没有**下沉。
2. **doubled 选择器**：`.badge` 基类留全局，而 module 规则在产物里排在全局之后、同特异性下会被吃掉（第四轮已实测），所以 `.badgeGoal` / `.badgeNote` / `.badgeTodo` 写成 doubled（`.badgeGoal.badgeGoal`）把特异性提到 (0,2,0)。`.badge-warning` 只声明 `background/color`，与基类无同属性冲突，不需要 doubled。
3. **原样保留既有层叠结果**：cards.css 里 `.badge-source` 在 `.badge-note-sm` 之前，同一个 Claude 徽章上一直是 note-sm 的 accent 底色胜出（既有行为）；module 里顺序照抄，探针实测仍是 accent-soft。
4. **`:global()` 后代规则同步改指本地类**：`ProjectCard.module.css` 原有 `.shell :global(.card-refresh-btn) { flex-shrink: 0; … }`，类名下沉后该规则不再命中，已改为 `.shell .cardRefreshBtn`；产物 CSS 已确认生成 `._shell_* ._cardRefreshBtn_*{flex-shrink:0;margin-left:2px;position:static}`。
5. **keyframes 随迁**：`@keyframes spin` 全站只被 `.spin` 引用，随之下沉，产物里变成作用域名 `_spin_*`，动画引用同步解析（探针实测 `animation-name: _spin_7ztxm_10`）。

## 三、校验结果

- `npm --prefix web run build` ✓（573ms）、`npm --prefix web run lint` 零输出（无告警无错误）、`npm --prefix web test` **15 文件 / 108 用例全过**。
- 类名对账：9 个组件逐个核对 module 定义与 `s.` / `css.` 引用，无未定义、无未引用（仅注释里出现的 `module.css` 字样被正则误捕，已排除）。
- 产物残留：当前 `index.html` 引用的 4 个 CSS + Settings 分片 CSS 里，`.skeleton-card` / `.tech-chip` / `.badge-*` / `.card-refresh-btn` / `.empty-section` / `.heatmap-empty-state` / `.skeleton-value` / `.skip-link` / `.main-content` / `.toggle-on` 全部零残留。
- 计算样式实测（探针页引用产物 CSS，`getComputedStyle`）：badge-goal 圆角 20px / padding 2px 9px（doubled 生效，未被基类 12px 吃掉）；tech-framework 取 info-soft/info；card-refresh-btn `absolute` + top 10px + right 36px；spin 动画名作用域化且解析成功；toggle-on 底色与边框均为 success、宽度 42px，knob `translateX(18px)`；skip-link `absolute` + top -40px + z-index 3000；main-content max-width 1280px + padding 32px + flex；empty-section/heatmap-empty-state/skeleton-value 的 padding/min-height/width 均符合原值。
  - 说明：以上 8 组实测跑在「修 `:global()` 回归」之前的那次构建上；其后唯一改动是第 4 条那条选择器重写，已在新产物 CSS 中静态确认，未影响上述任何一项。
